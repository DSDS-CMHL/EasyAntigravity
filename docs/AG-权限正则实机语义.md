# AG 权限正则实机语义

## 验证边界

2026-10-11，用户在 AG 桌面端手动验证。当前 EasyAG 发布版本为 v3.1.0；未记录 AG 的具体版本，结论不得无条件推广到其他版本。
这里只记录 AG 原生 Ask 的实际表现；ARES 风险通知不作为 Ask 命中的证据。本地 JavaScript RegExp 模拟通过，也不代表 AG 支持相同语法。
每次仅添加一条临时 Ask 规则，确认重新加载，完成后移除；保留用户原有 Allow / Deny / Ask 配置。所有命令都是 echo 打印，不执行其中的危险操作。

维护约束：当前原生权限规则不能依赖 `(?=...)` 或 `(?!...)`。尚无 AG 内部解析证据，不能断言具体使用了哪种正则引擎或如何处理无效表达式。

同轮反馈：下载交给解释器的探针命中 Ask，并显示 ARES 风险说明；点击“前往审查”后通知未重复弹出。`echo rm -rf` 与 `echo git push -force` 未命中 Ask。这两条对应的 v3.1.0 合并权限规则包含前瞻；下面 M1–M3 的实机结果支持前瞻影响整条合并表达式的解释。

## 已完成：最小补充验证

每次仅保留表中该条临时 Ask 资源，确认加载后执行对应命令。预期只指审批；ARES 是否出现不影响判断。

| 编号 | 临时 Ask 资源 | 安全测试命令 | 待验证假设 | 实机结果 |
| --- | --- | --- | --- | --- |
| M1 | `command(regex:.*(?:easyag-lookahead-probe|(?=easyag-unused-probe)easyag-unused-probe).*)` | `echo 'easyag-lookahead-probe'` | 前瞻仅在不参与匹配的另一个分支中，是否仍使整条规则失效 | 自动放行；ARES 未记录 |
| M2 | `command(regex:.*\brm\s+-rf\b.*)` | `echo 'rm -rf'` | 不含前瞻的简单删除规则应命中 Ask | 命中 Ask；ARES 高风险弹窗 |
| M3 | `command(regex:.*\bgit\s+push\s+--?force\b.*)` | `echo 'git push -force'` | 不含前瞻的简单强推规则应命中 Ask | 命中 Ask；ARES 中风险弹窗 |

用户于 2026-10-11 反馈 M1 放行、M2/M3 命中 Ask。这支持“含前瞻的合并表达式整体不生效”的解释，并实证简单无前瞻表达式可覆盖这两个探针。正向前瞻污染另一分支已经实测；负向前瞻的跨分支影响未单独实测，L3 仅确认负向前瞻样例自身未命中。

### 后续维护约束

- 写入 AG 原生权限的表达式不得依赖正向或负向前瞻，不得将含前瞻的分支混入其他可用分支。
- 不得仅以 JavaScript 正则编译成功或本地匹配通过认定原生权限规则可用。
- 前瞻兼容问题不能通过粗暴删除断言解决：例如移除排除预演的负向前瞻会重新引入误报，必须重新设计表达式并验证正负样例。
- 实机结果只证明上面的具体样例，不代表完整生产规则已经验收。

## 源码修正（待生产规则实机验收）

2026-10-11，`danger-rules.json` 升至规则版本 6（不是应用发布版本），权限分发包升至版本 5：

- 删除：把末尾前瞻改为消耗式参数边界，保留参数在目标路径之后的匹配。
- Git：强推、硬重置与历史重写保留独立分支；clean 用可接受参数序列匹配完整命令段，短选项排除 n/N，长选项用有限分支排除完整 dry-run。边界限制在当前命令段，避免后一条命令的 -n 影响前一条 clean；保留带空格的引号路径。
- 磁盘工具：显式匹配 diskpart 的启动或非帮助参数，排除 /?，不依赖负向前瞻。
- 持久化：crontab 显式匹配编辑、移除、交互及导入形态，纯 -l / --help 不匹配；其他计划任务和服务分支不含前瞻。
- 精确匹配已知旧版默认表达式时升级；用户自定义表达式、大小写设置、启停和审批动作不被覆盖。
- 原生权限编译器拒绝前瞻，并保守拒绝未经本轮验证的后顾；报错指出规则编号。ARES 仍使用本地 JavaScript 正则，不受此限制。

这些改动仅完成源码和本地回归验证，未通过 AG 验收新的完整合并表达式，也未构建或推送。已有扩展边界缺口仍见扩展攻防记录，不能据此宣称兜底所有危险命令。

验证记录：`npm run check`、`npm test`、默认权限规则与权限分发包校验均通过。首次完整测试受到沙箱临时文件重命名和本地模拟通信权限限制，正常权限重跑完整测试通过；测试没有连接真实 AG 或改动其配置。新增回归覆盖断言拒绝、无害字面量不误拒绝、旧版模式迁移、删除/强推探针、Git 预演参数及带空格路径。扩展审计仍有 7 条审批漏报、7 条审批误报和 13 条通知存在性差异，明确保留为待修项。

这些简单表达式仅用于定位问题，不是完整生产规则：尚未覆盖参数顺序、大小写、路径、预演参数等边界。
