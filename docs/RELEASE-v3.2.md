# EasyAG v3.2 系列新特性

EasyAG 是 Antigravity 桌面端的增强启动器：负责代理、汉化和可恢复的权限增强，让用户启动后专注于 AG，而不是另一套工作台。

本文面向分发说明与使用介绍。本轮应用版本为 v3.2.4，包含最终的圆润盾牌与 99+ 上限；旧版便携包不会自动更新，需要下载对应版本。

## 两种启动模式

### Turbo Pilot：自动执行，风险操作再确认

Pilot 将开启命令自动执行和配置危险命令审批的操作一键化。普通命令尽量减少手动审批，命中原生 Ask 规则的操作交由用户确认。ARES 另外提供风险等级与可能后果，帮助理解审批原因。

Pilot 不等于替用户全面切换 AG 的原生 Turbo 预设：它写入命令自动执行策略并叠加权限规则，不主动改变用户的文件访问、工作区外访问或沙箱设置。因此 AG 设置界面可能显示“自定义”。

### 兼容模式：沿用用户权限设置

兼容模式不注入 Pilot 审批规则，不开启 Pilot 的 ARES 风险提醒，也不更改命令自动执行策略。代理、汉化和已开启的上下文显示仍可使用，适合只希望增强连接与中文界面的用户。

## 三档防护强度

| 档位 | 设计取向 |
| --- | --- |
| 严格 | 对部分高风险命令采用更宽泛的文本匹配，宁可增加审批，也可能拦到打印或示例文本。 |
| 标准 | 默认档位，覆盖常见破坏性命令及参数形态，尽量区分参数边界和部分预演操作。 |
| 宽松 | 删除类规则聚焦关键路径，并保留磁盘破坏、凭据、备份、数据库和远端脚本执行等关键风险；审批范围更小。 |

强度控制默认规则的审批范围，不改变用户自定义规则的动作和启停状态。ARES 的风险评估与原生审批分开，某条命令没有触发审批，也可能显示风险提醒。防护档位在运行期间锁定，下次启动时应用。

## AG 输入区中的轻量指标

### 上下文圆环

用圆环及加粗数字展示最近请求的上下文占用估算，不另做额度面板。点击可查看占用、容量、模型和最近有效请求的生成速度。容量未知时不伪造百分比；压缩后占用可能下降。速度只放在详情中，不占常驻位置。

### 最近风险盾牌

圆润细线盾牌内显示最近一次风险命中等级的会话累计次数：高风险红色、中风险黄色、低风险蓝色。不按时间轮播，不固定停留在历史最高风险等级；普通命令不改变最近风险状态。

- 0–99 显示准确数字，100 起显示 99+，按位数调整字体。
- 悬浮说明保留该等级的准确次数；点击详情查看高、中、低和总计。
- 无风险记录时显示中性 0，尚未同步时显示 —。
- 同一命令执行不因审批状态或通知开关变化重复计数；切换对话不清零，开始新 AG 会话时清零。
- 风险详情卡收窄至 208px，上下文详情卡保持原尺寸。

计数来自 ARES 风险命中，不是成功拦截次数，也不是审批允许/拒绝结果。它不向统计面板传递命令全文，不恢复历史会话统计。

## 规则重载与配置恢复

运行中的 Pilot 可以重载规则。重载不仅更新风险识别，也更新 AG 的原生权限；新增、禁用或移除的本会话规则按最新配置替换。兼容模式重载不会写入 AG 权限。

EasyAG 记录自身新增的规则及注入前的策略，退出时撤回自己的增强，而不是套用一个默认预设或整份覆盖用户配置。重载后新增规则也纳入恢复记录，运行期间用户在 AG 界面新增的规则会保留。

修复 issue #7：权限字段为空对象、缺失数组或 null 时，按需补齐并记录原结构；非法非空结构报错，不以空配置覆盖用户数据。

## 胶囊通知与前往审查

风险胶囊提供风险等级和可能后果，可手动关闭或前往 AG 审查。审查跳转改为单次请求，先隐藏胶囊，再激活 AG 原生窗口，避免重复唤起竞争。

v3.2.3 原生胶囊设为不可获取输入焦点；审查按钮拒绝键盘产生的默认点击，不绑定回车或空格跳转。EasyAG 不模拟鼠标点击，不替用户允许或拒绝审批。

## 验证状态与安全边界

截至 2026-10-12，已有用户实机确认：新增规则重载生效、重复规则纠正后的禁用重载表现正常、重载后正常退出恢复、AG GUI 新增规则退出后保留、兼容模式沿用用户配置。便携补丁的审批框显示问题已获用户确认改善。

原生胶囊不抢焦点、键盘误触阻断，以及最终圆润盾牌和 99+ 外观，仍需对应新构建实机验收。异常退出恢复按用户选择暂不实测，不列为已通过。完整默认规则与三档的所有命令变体没有全部实机验收，已知误报和漏报仍有记录。

ARES 是风险辅助，不是防病毒软件或完整安全隔离。正则无法穷尽所有命令变体；通知出现不等于命令已被阻止。重要操作仍需核对目标、权限与备份。

URL 的全量 Allow 配合指定域名 Ask/Deny，以及 Deny > Ask > Allow 已有具体样例实机确认，但本轮没有将 URL 黑名单自动注入做成新功能。网络读取 read_url 与浏览器操作 execute_url、终端命令 command 是不同权限，不应混用。
