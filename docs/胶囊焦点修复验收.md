# 胶囊焦点修复验收

## 实机现象与诊断边界

2026-10-12，用户反馈其他应用中触发风险通知、点击前往审查后，AG 审批框需要再点击或切换应用才能显示。在 AG 内触发则正常；打字时空格或回车可能误触前往审查。

只读抓取时，Windows 前台为 AG，胶囊隐藏，AG 文档 hasFocus 为 true、visibilityState 为 hidden，命令步骤仍等待用户输入。用户切回聊天后报告审批框出现；后续抓取 hasFocus 为 false、visibilityState 仍为 hidden，且主文档未定位到审批框。因此不将 hidden 状态单独认定为根因。

## 便携包补丁实测

对 v3.2.2 便携包的 src/capsule.html、desktop/api.js、desktop/host.js 做备份补丁，并同步源码：

- 单次请求、点击处理中去重，不再并行广播多个地址或重复发送 Beacon 和 fetch。
- 后台先隐藏胶囊，等待 180ms 让异步原生隐藏处理，再激活 AG 原生窗口；不模拟点击或按键，不操作审批。
- 原生激活等待返回值并记录失败；Windows/macOS 不再先用 CDP bringToFront 与胶囊隐藏竞争。
- 阻止按钮空格/回车默认激活，去掉回车提示。

用户实测反馈：审批框正常显示，但胶囊仍抢焦点，回车仍可能跳转。前一部分验收通过，原生焦点及键盘误触问题仍待新构建验证。

## v3.2.3 修复

- 胶囊创建时 focusable(false)，而不仅是 focused(false)；每次显示前再次 set_focusable(false)，若设置失败则不显示，避免通知抢输入。
- 前往审查只接受明确指针点击；detail=0 的键盘或程序化点击不触发。显示通知时清除残留按钮焦点。
- 保留隐藏后再激活的便携补丁，不对 AG 页面或审批状态作修改。

本地语法与胶囊回归检查通过；原生窗口行为交由云端构建后实机验证。验收重点：其他应用持续打字时弹出通知不抢输入、空格/回车不跳转、鼠标仍能关闭及前往审查、审批无需额外窗口切换、重复通知与快速连续点击无异常。
