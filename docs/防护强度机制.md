# 防护强度机制

## 产品语义

“防护强度”控制 EasyAG 向 AG 叠加哪些原生审批规则，不是 ARES 风险等级，也不是杀毒或完整命令沙箱。默认使用标准档；三档均为 Turbo Pilot 的可选审批策略，危险特征默认要求 Ask，不新增默认 Deny。

| 档位 | 原生审批范围 | 用户取舍 |
| --- | --- | --- |
| 严格 strict | 标准规则加宽泛删除、Git 危险文本特征；不排除这些特征中的文件名或预演 | 更容易打断正常操作，不保证覆盖所有变体 |
| 标准 standard（默认） | 识别常见命令、参数及命令边界；支持 rm 的选项结束符与常见 Git 全局选项，排除 Git clean 的明确预演 | 平衡误报与覆盖，仍有已记录缺口 |
| 宽松 relaxed | 删除规则缩小到字面根目录、主要系统/用户目录及敏感凭据目标；保留磁盘、裸设备、凭据、备份、数据库破坏和下载执行规则 | 有限防护，普通项目删除、Git 破坏等不由默认档位要求审批；漏报风险较高 |

ARES 在所有 Pilot 档位继续开启，按命令及后果独立解释风险。降低防护强度不会降低通知等级，也不会关闭风险提示。通知不能阻止执行：宽松档可能自动执行同时提示高风险；严格档也可能对 ARES 没有明确危险解释的文本要求审批。

## 面板交互

- 原 ARES 灰色开关替换为三个按钮：严格、标准（默认）、宽松；每档下方显示简短取舍说明。
- 兼容模式不应用防护档位，按钮不可选；保存已有偏好，切回 Pilot 后恢复选择。兼容模式仍只沿用用户默认审批，ARES 不开启。
- 准备、启动和运行期间禁止切换防护强度、模式和端口；界面锁定，后端也拒绝变更。汉化仍可实时切换。
- 点击档位仅保存 EasyAG 偏好，不立即修改真实 AG 配置。实际规则在启动 AG 前生成、写入、校验；日志记录档位和规则数量。
- 保存失败会恢复服务器上已保存的选择，避免显示一个没有保存成功的档位。
- 宽松档用警示文案提示有限防护，不使用“安全模式”或“无风险”称呼。

## 模块边界

- `core/settings.js`：持久化 `protectionLevel`，仅接受 strict/standard/relaxed；缺失字段使用 standard。保留旧 riskAdvisor 字段的兼容行为，但它由启动模式决定，不再提供独立开关。
- `features/command-patterns.js`：可读的正则构造片段，生成 rm 参数边界及 Git 全局选项、clean 预演排除。禁止前瞻/后顾。
- `features/protection.js`：纯函数生成档位对应的规则视图，不改写用户规则文件、不负责通知、不读写 AG 配置。
- `features/rules.js`：加载和迁移默认规则，编译选定档位到 Allow/Deny/Ask；ARES 使用标准语义与独立知识库判断风险，不按防护档位筛除风险通知。
- `core/session.js`：启动时捕获档位，生成规则并调用已有可恢复配置叠加层；退出或失败清除活跃档位。
- `adapters/desktop/permissions.js`：维持原有 journal 叠加与恢复机制，不因档位引入另一套写入逻辑，也不改变工作区外访问或沙箱设置。
- `desktop/application.js` / `desktop/api.js`：校验设置变更，状态区分保存的 protectionLevel 和会话 activeProtectionLevel，手动同步也使用保存的档位。
- `ui/launcher.js`：显示和保存选择，锁定控件，提示生效时机；不生成正则。

## 用户规则与兼容性

预设只调整模式、flags 与内置当前版本完全一致，且没有显式 action 的默认规则。用户自定义 pattern、flags、额外规则或显式 Allow/Deny/Ask 不被削弱或替换；disabled 规则不因切换档位重新开启。自定义规则可能使宽松档仍出现额外审批，这是保留用户设置的预期行为。

默认规则版本 7 精确迁移已知旧版默认删除、Git 表达式，保留用户启停、命名及审批动作。ARES 知识版本 3.0.2 对应修正 rm 文件名与 Git 全局选项检测，两个分发/兼容副本由现有同步工具更新。

## 验证范围

本地检查覆盖三档审批差异、设置校验与旧设置缺省、实时变更锁定、启动档位捕获、退出清理、用户规则保留、通知独立，以及面板保存/锁定/失败恢复。命令只作字符串输入，没有执行危险操作或改变真实 AG 配置。

已通过语法检查、完整本地回归、默认权限规则与分发包校验。面板交互验证使用模拟 DOM，未进行原生窗口视觉验收，也未构建或推送本轮机制。

最小实机验收矩阵（下面是源码目标，不是已通过的实机结果）：

| 安全探针 | 严格 | 标准 | 宽松 |
| --- | --- | --- | --- |
| `echo 'rm -- -rf'` | Ask（接受误报） | 自动执行 | 自动执行 |
| `echo 'git -C . clean -fdx'` | Ask | Ask | 自动执行 |
| `echo 'git clean -nfdx'` | Ask（接受预演误报） | 自动执行 | 自动执行 |
| `echo 'rm -rf /'` | Ask | Ask | Ask |

必须完整保留 echo 和引号；不能执行真实删除来验证。每档应先退出 AG 后通过 EasyAG 启动，并确保没有手动实验留下的额外临时规则影响对照。所有结果仍需按 AG 版本记录，不能把本地 JavaScript 匹配当成原生审批支持证明。

当前标准档扩展审计仍有 5 条审批漏报、6 条审批误报及 10 条通知存在性差异，见扩展攻防记录。宽松档只识别字面目标，不解析真实工作目录、路径规范化、变量或命令替换；严格档也不能穷尽编码、别名与所有工具变体。
