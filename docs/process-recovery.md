# AG 进程冲突恢复

AG 关闭窗口或退出后，sidecar 等进程可能继续使用同一个可执行文件运行。
EasyAG 保留原有进程检测，不会自动结束这些进程。

- 启动检查发现已有进程时，返回 `PROCESS_CONFLICT` 并显示专用处理窗口。
- 运行中点击原启动按钮，也可打开处理窗口。不增加常驻重启按钮。
- 用户点击“清理并重新启动”后，停止增强连接，清理所选安装的当前用户进程，确认退出后沿用正常启动检查。
- 用户应先保存工作、结束需要保留的任务。窗口和后台进程都会受影响。
- 路径不存在单独返回 `TARGET_NOT_FOUND`。其他错误记入日志，不再统一弹路径窗口。
- 清理失败时不继续启动，保留错误提示和重试入口；清理中禁止重复启动与修改启动设置。

Windows 按解析后的可执行文件完整路径、进程所属用户筛选，不使用 `taskkill /IM`。
macOS 按当前用户和所选应用包内的可执行文件路径筛选，包含 Helper。
发送退出信号前再次比对 PID 和创建时间，降低 PID 重用导致的误处理风险。
先尝试退出，超时后强制结束并重新查询；Windows 上 Node 的进程终止本身属于强制结束。
不通过父进程树扩大清理范围，不结束项目启动的任意其他程序。

新增运行模块已经加入热更新清单生成脚本；实际发布时仍需随版本生成新清单。

## 验证范围

单元测试覆盖安装路径隔离、所有者查询、PID 重用、清理失败、重复请求、退出取消和重新启动检查。
浏览器测试使用模拟后台覆盖冲突弹窗、取消、失败重试、运行中入口以及路径错误分流。
Windows 真实进程枚举已只读验证；不会在测试中清理用户的真实 AG。
macOS 的实际进程终止仍需对应环境验证。
