## 一、它实际提供什么

| 功能 | 数据来源与含义 | EasyAG 建议 |
| --- | --- | --- |
| 额度 | 账号额度组的 5 小时/每周剩余比例、重置时间；并非所有账号必定返回所有窗口 | 首批接入 |
| 生成速度 | 最近有效请求与会话加权 tok/s；不是限速器，也不是逐 token 的瞬时速度 | 首批接入，优先最近请求 |
| 首 token 等待 | 后台请求元数据中的 TTFT，现有汇总为有效请求平均值 | 可放详情 |
| 上下文 | 最近请求开始时的宿主估算占用与容量，不是累积输入量 | 第二批，或首批详情展示 |
| 缓存命中 | 请求元数据中的缓存读取与输入 token 计数 | 后续按需加入 |
| 工具耗时 | 工具执行区间的并集，重叠执行不重复计时 | 暂不需要 |
| 历史恢复 | 按账号与对话保存白名单统计，断线后显示旧采样 | 暂缓，先做好实时与过期状态 |
| 内嵌统计条 | 输入区模型选择器附近，子代理使用独立输入区锚点 | 借鉴形态，自己实现 |
| 原生辅助侧面板 | 宿主 sidecar SDK 的 Auxiliary Pane 入口 | 非首批依赖 |
| CLI 状态栏 | 独立 CLI statusLine 适配 | 不接入 |

## 二、两条链路，不能混为一谈

数据链路：当前用户语言服务进程 → PID 所属 HTTP 端口与该进程 CSRF 凭据 → 本地 RPC → 数值归一化 → 统计快照。

展示链路：AG 调试端口 → CDP 绑定桥 → 当前页面/对话识别 → Shadow DOM 统计条。

它的默认内嵌条是运行时 DOM 注入，不是 AG 官方公开的模型选择器插槽。原生辅助面板才走 sidecar SDK。这两种展示机制不同。

默认路径不依赖修改 `app.asar`；仓库仍保留旧补丁迁移与显式 legacy 安装逻辑。安装器会注册、启用宿主插件，并且迁移时可能恢复旧归档，因此不应直接作为 EasyAG 接入步骤。

## 三、可复用的接口知识

本地接口前缀：`/exa.language_server_pb.LanguageServerService/`。

请求是 loopback HTTP POST JSON，带 `Connect-Protocol-Version: 1` 与 `x-codeium-csrf-token`。凭据与端口必须属于同一个语言服务进程，不能从旧环境或另一实例拼接。

| 方法 | 用途 |
| --- | --- |
| `GetUserStatus` | 确认账号作用域；参考实现用邮箱哈希隔离缓存 |
| `RetrieveUserQuotaSummary` | 读取额度组与额度窗口 |
| `GetCascadeTrajectory` | 获取指定对话轨迹与请求元数据 |
| `GetCascadeTrajectoryGeneratorMetadata` | 补齐元数据分页，使用 `generatorMetadataOffset` |
| `GetCascadeTrajectorySteps` | 补齐步骤分页，使用 `stepOffset` |
| `GetAllCascadeTrajectories` | 枚举对话；已知当前 ID 时不必调用 |

这些是参考项目使用的宿主内部接口，不应视为稳定公共 API。要独立做版本/能力探测和失败降级。

进程发现实现支持 Windows、macOS、Linux，并验证监听端口的 PID 归属。它遇到多个 standalone 后台会拒绝猜测。EasyAG 应优先利用自身启动会话绑定实例，不能照搬“机器上只能有一个后台”的前提。

## 四、应保留的统计口径

1. 最近请求速度 = 可见输出 token / 有效 streamingDuration。
2. 会话速度 = 所有有效样本可见输出 token 总和 / 对应 streamingDuration 总和，不是各请求速度的算术平均。
3. TTFT、思考时间和工具时间不能直接塞进流式输出速度的分母。输出字段不全时要标明回退口径；缺时长不编造速度。
4. 请求按 messageId/executionId 去重；分页失败不能把残缺数据当完整会话。
5. 缓存比例按 token 加权，缓存写入不算命中。参考实现按 AG 返回的“非缓存 inputTokens”再加缓存读写；接入时必须在本机确认字段语义。
6. 上下文使用最近请求的 `estimatedTokensUsed/maxContextTokens`；容量缺失不靠模型名猜，压缩后占用下降应正常更新。
7. 额度真实 0、未知、窗口未提供、禁用、失联、旧缓存必须区别显示。重置倒计时结束只能请求刷新，不能假定余额恢复。

参考缓存策略：额度约 60 秒、会话约 1.8 秒；控件可见时约 2.2 秒采集，页面隐藏时约 10 秒。请求合并、超时与断线清理比追求极高刷新频率重要。

## 五、值得借鉴的可靠性设计

- 账号切换、后台重启、对话切换都改变请求代次；旧响应不能覆盖新状态。
- 导航立即清空上一对话统计，不等待旧请求结束。
- 重复注入幂等；停止时清除自身绑定、脚本、定时器、观察器与控件。
- 凭据留在后台内存，不传给渲染页面或写入日志。
- 桥接只接受有限类型与合法对话 ID，限制消息大小、并发及超时。
- 限定主页面与来源，不能让远程页面或 iframe 获得统计桥接能力。
- Shadow DOM 隔离样式；挂载歧义、不安全布局或遮挡原生控件时宁可不显示。
- 窄窗口采用紧凑模式，再不足则隐藏；详情支持 Escape、外部点击与可靠清理。

不必搬运它的 Python 安装器、常驻 sidecar、SDK 二进制提取、实例接管文件及历史补存工具。EasyAG 已有桌面会话生命周期与 `adapters/desktop/cdp.js`，应在现有边界内扩展。

## 六、阅读中发现的接入注意点

- `quotaMetrics` 用 `Number(remainingFraction)` 转换，`null` 和空字符串会变成 0；现有额度测试未覆盖这两个输入。我们应严格区分未知与真实零。
- 历史文件是统计白名单，但对话枚举会产生标题并进入快照。不能把“历史不保存正文”扩大成“所有前端载荷完全没有标题”。EasyAG 首版不枚举其他对话，输出只做数值白名单。
- 原始轨迹可能含正文，虽然只展示统计，采集阶段仍会接触敏感内容。应避免持久化、原样日志与不必要的完整轨迹查询。
- 内嵌条依赖宿主 DOM，辅助侧面板依赖 SDK。源码与模拟测试通过不能证明本机、全部版本或所有系统兼容。
- 极短输出样本可能出现很高 tok/s；不等同于用户体感吞吐量，也不能据此承诺模型性能。
- MIT 允许按其条件复用源码；如果实际复制或改编实现，应保留对应版权与许可证声明。

## 七、EasyAG 的建议落点

第一阶段只做“额度与生成速度”监控，不做账号切换、额度管理或主动限速。

- 独立语言服务适配层：发现正确实例、只读 RPC、能力探测、断线重连。
- 独立统计模块：额度归一化、请求去重、速度计算、账号/对话缓存隔离。
- 通过现有 CDP 中枢展示轻量统计条，详情放剩余额度、重置时间、最近速度与等待时间。
- 监控开关与 Pilot/兼容模式独立；监控是只读功能，不需要改变审批权限。
- 默认不保存历史、不读取其他对话、不增加第三方插件安装依赖。
- 不可用时显示明确状态，不能妨碍汉化、代理、启动和 ARES。

下一步应先做本机只读能力验证，确认接口字段、当前对话 ID 和账号隔离，再实现正式模块；本次阅读没有进行这一操作。
