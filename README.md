EasyAG 是 Antigravity 桌面端的增强启动器。它在 AG 启动前帮你配好代理、写入权限规则，启动后缩进系统托盘，不挡路。你还是在 AG 里正常工作——只有遇到危险命令或上下文快满的时候，它才会出来提示你一下。

**它不替代 AG，也不替你点"允许"。**

填好代理端口、选好汉化和启动模式，点一下就进 AG。不需要在 EasyAG 里另开一套对话窗口。

## 两种启动模式

### Turbo Pilot：普通命令自动过，危险命令停下来审

开启 Pilot 后，EasyAG 会自动把"允许命令执行"和"危险命令审批规则"一起写进 AG。日常操作不用反复点允许；命中危险规则的命令仍然走 **AG 原生审批流程**，ARES 负责解释为什么危险。

这不是"全部放行"，而是把你的注意力集中到真正需要确认的地方。

防护强度分三档，影响的是哪些命令会触发审批：

| 防护强度 | 说明 |
| --- | --- |
| 严格 | 匹配更宽泛——递归删除、git 强推等危险文本覆盖更多写法，误报也会更多。 |
| 标准（默认） | 识别常见危险命令和参数，尽量减少对正常命令的误报。 |
| 宽松 | 只保留部分明确高危操作的审批，漏掉危险命令的可能性更大。 |

三个档位只影响 EasyAG 内置的默认规则，你自己加的自定义规则不受影响。档位在 AG 运行期间不能切换，退出 AG 后再改，下次启动时生效。

### 兼容模式：只设代理和汉化，不动权限

如果你只想用代理、汉化功能，或者已经有一套自己的权限配置，选兼容模式就好。

兼容模式**不会注入 Pilot 规则、不会改自动执行策略、也不会开 ARES 风险提醒**。上下文监控功能如果开了，还是照常显示。

无论哪种模式，EasyAG 都不会扩大 AG 的工作区外文件访问权限或沙箱范围——该由你在 AG 里决定的，还是由你决定。

## 风险提醒：说清楚会出什么事，不只是亮个红灯

<p align="center">
  <img src="docs/images/risk-capsule.png" width="480" alt="ARES 风险胶囊演示：递归删除可能造成的后果">
</p>

光说"这是危险命令"没什么用。ARES 会告诉你：**风险是高、中还是低，触发了什么操作，可能造成什么后果**——比如把某个目录的文件全删掉、把远端提交历史覆盖掉、或者执行了一个来源不明的脚本。

提示出现后，你可以关掉胶囊，也可以点"前往审查"回到 AG 确认。最终执不执行，还是你说了算。

> 胶囊通知只是提醒，不是拦截。看到提醒不代表命令已经被阻止了。

## 两个小图标，随时掌握状态

### 风险统计 · AG 实机截图

![AG 输入区的风险盾牌与分级统计](docs/images/risk-stats-live.png)

### 上下文详情 · AG 实机截图

![AG 输入区的上下文圆环与请求详情](docs/images/context-stats-live.png)

这两个标识嵌在 AG 的输入区里，不用打开启动器就能看到：

- **上下文圆环**：大概显示当前这轮对话用掉了多少上下文空间。点一下能看容量和模型名称，生成速度也在里面，但不是主要信息。
- **风险盾牌**：颜色代表最近一次命中风险的等级，数字是这个等级在本次 AG 会话里累计触发了多少次。数字超过 99 显示 `99+`，悬浮或点击可以看准确数字，以及高、中、低各自的计数。

普通命令不会改变盾牌颜色；同一条命令重复出现不会重复计数；切换对话不清零；新开一个 AG 会话才会从零开始。

上下文的数字是估算，容量不确定时不会瞎编一个百分比，上下文压缩后数字可能会下降，这都是正常的。

## EasyAG 不会乱改你的设置

Pilot 启动时会先记下你原来的配置，然后只追加自己的规则。退出 AG 后，EasyAG 会撤掉自己加进去的规则，把配置还原——**不是把你的配置整个替换成一份默认模板**。

你在 AG 界面里自己加的规则，退出后应当保留。这几点已经实机验过：

- 追加规则、禁用规则后点"重载规则"，能正常生效。
- 重载后正常退出 AG，本次会话注入的内容（包括检测探针）会全部撤回。
- AG 运行期间通过界面新增的用户规则，退出后保留。
- 兼容模式下沿用你自己的权限配置。

如果 AG 异常退出，下次启动 EasyAG 时会尝试处理上次未完成的恢复。**异常退出恢复这个流程还没有做实机验收**，暂时别手动删掉那些恢复记录。

## 三步开始

1. **把压缩包完整解压**到一个目录里。Windows 运行 `EasyAntigravity.exe`，不要把这个 exe 单独拿出来放别处。
2. 打开你用的代理软件，填入它的 **HTTP 或 Mixed 端口**（EasyAG 本身不提供代理，只是帮 AG 用上你已有的代理）。
3. 选好汉化和启动模式，点"启动"。如果 AG 已经在运行，先退出它，再通过 EasyAG 重新启动，这样 Pilot 的配置才能生效。

Windows 包里自带了 Node.js，不需要额外装开发环境。界面需要 WebView2，Windows 10/11 通常已经自带。macOS 的 Apple Silicon 和 Intel 构建目前是 Beta 状态。

[去 GitHub Actions 下载构建包](https://github.com/DSDS-CMHL/EasyAntigravity/actions/workflows/tauri-ci.yml)——打开一个显示成功的构建，在 Artifacts 里下载对应平台的压缩包。下载附件可能需要登录 GitHub。

关窗口只是最小化到托盘，**不是退出**。想彻底退出 EasyAG，在托盘图标上右键选"退出应用"。升级时把新包解压到一个新目录，不要覆盖旧目录，防止旧快捷方式失效。

## 常见问题

**AG 里显示的是"自定义"，不是"Turbo"，是没生效吗？**  
不是。Pilot 是把自动执行策略和审批规则组合起来用，同时保留你的其他权限选项，所以 AG 会显示"自定义"而不是某个预设标签。显示"自定义"说明生效了。

**改了规则，需要重启 AG 吗？**  
不用完全重启。Pilot 运行时点"重载规则"就可以更新，改动会同步写入 AG 的权限设置。但如果 Pilot 还没启动，或者当前是兼容模式，重载只更新本地记录，不会写入 AG。另外注意：同一条规则别存两份，禁用一份不会让另一份启用的副本也禁用。

**能拦住所有危险命令吗？**  
不能。规则基于正则匹配，覆盖不了所有写法，误报和漏报都会有。ARES 不是杀毒软件，也不是沙箱。涉及重要操作时，还是要自己核实目标路径、权限范围和备份情况。

**支持 AG IDE 或命令行版本吗？**  
目前只针对 AG 桌面端，IDE 和 CLI 还没有适配。旧版的 Hook 拦截机制已经移除了。

**会动 AG 的安装文件吗？**  
不会。界面增强通过 CDP（Chrome 调试协议）注入，权限配置通过叠加方式写入；AG 的安装目录不会被修改。注意 CDP 调试端口只应该在本机使用，不要把它暴露到局域网或公网。

## 开发

技术栈：前端 HTML/CSS/JavaScript，后端模块化 Node.js，原生窗口和托盘用 Tauri（Rust）实现。

```sh
npm ci          # 安装依赖
npm start       # 开发模式启动
npm run check   # 代码检查
npm test        # 运行测试
```

需要 Node.js 22 或更高版本。打包原生应用还需要 Rust 和 Tauri 的构建环境。

重新生成 README 里的演示截图：

```sh
node scripts/capture-readme.cjs "<Chromium 可执行文件路径>"
```

这个脚本只启动一个独立的浏览器实例和演示服务器，不会连接或改动真实的 AG 配置。
