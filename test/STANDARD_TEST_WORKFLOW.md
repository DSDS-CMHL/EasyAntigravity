## 一、测试目标与覆盖矩阵

| 序号 | 测试项 | 核心行为 / 校验点 | 预期日志标签 / 颜色 |
| :--- | :--- | :--- | :--- |
| **01** | **自动审批** | 安全命令自动选择配置选项（如仅允许本次），自动点击放行 | `AUTO-ACCEPT` / `tag-proxy` (绿色/主色) |
| **02** | **危险拦截** | 命中高危正则（如 force push / rmdir），按钮打上 blocked 标签，拒绝放行 | `SECURITY ALERT` / `tag-alert` (红色高亮呼吸动效) |
| **03** | **拦截后解锁** | 用户手动放行或卡片关闭后，锁定标记立即销毁，后续安全命令即刻恢复自动审批 | `AUTO-ACCEPT` / `tag-proxy` |
| **04** | **问答停止交互** | 识别非权限业务问答框（单选项无 allow/允许 特征），审批绝对暂停，等待用户选择 | `INTERACTION` / `tag-mint` (**薄荷荧光青 #00f5d4**) |
| **05** | **问答后解锁** | 用户在 IDE 提交选择后卡片关闭，后续执行工具命令无缝恢复自动审批 | `AUTO-ACCEPT` / `tag-proxy` |
| **06** | **规则热重载** | 调用重载接口或更新规则，无需重启进程，内存实时刷新生效规则数 | `SECURITY` / `tag-proxy` |
| **07** | **重载后拦截** | 刚刚动态添加的自定义规则立即生效，精确拦截新定义的危险指令 | `SECURITY ALERT` / `tag-alert` |
| **08** | **日志流校对** | 检查全过程日志流的时间顺序、类型分类与关键字段，确保无漏报无乱序 | 全日志流综合校对 |

## 三、交互式人工端到端（E2E）标准测试流程

配合 Antigravity IDE 与 EasyAntigravity 图形界面进行真实实操联调时，请按顺序执行以下 8 个步骤：

### 阶段 1：自动审批测试
1. **前置条件**：打开 EasyAG，确认控制台右上角或配置面板中「自动审批」处于开启状态。
2. **触发操作**：在 Antigravity 聊天窗口中让 Agent 运行一个安全的只读命令，例如：
   > *“请帮我执行 `git status` 查看当前代码状态”*
3. **预期表现**：
   - 界面弹出授权卡片后，在 200ms 内自动选中首选选项（如“仅允许本次”），并自动点击 Continue / Allow。
   - EasyAG 界面日志输出绿色 `[AUTO-ACCEPT]`，审批通过计数器 +1。

---

### 阶段 2：高危指令熔断拦截测试
1. **触发操作**：在聊天窗口中让 Agent 尝试执行危险命令，例如：
   > *“请帮我执行 `git push origin main --force` 提交代码”*
2. **预期表现**：
   - EasyAG 立即捕获该指令，**绝对禁止自动点击**。
   - 按钮被打上 `data-ea-ok="blocked"` 属性，审批卡片保持在屏幕上，等待用户手动决策。
   - EasyAG 窗口自动弹前，日志区域打印出带有**红色呼吸闪烁**的 `[SECURITY ALERT]` 告警：
     ```text
     [SECURITY ALERT] 拦截高危指令[git-force-push]，等待用户手动确认: git push origin main --force
     ```
   - 拦截计数器（Block Count）+1。

---

### 阶段 3：拦截后解锁（恢复自动审批）
1. **触发操作**：
   - 方式 A：用户在 Antigravity 界面上点击“Reject / 取消”，关闭该高危卡片。
   - 方式 B：用户确认安全后，手动点击“Allow”按钮放行该指令。
2. **验证恢复**：高危卡片消失后，立即让 Agent 执行普通命令：
   > *“帮我运行 `git branch -a`”*
3. **预期表现**：
   - 系统检测到活动阻塞已消除，`window.__ea_danger_lock` 自动重置为 `null`。
   - `git branch -a` 正常触发自动审批放行，不需要重启 EasyAG，证明**拦截之后解锁成功**。

---

### 阶段 4：方案问答卡片停止交互（薄荷荧光青）
1. **触发操作**：在对话中让 Agent 触发方案多选问答（调用 `ask_question`），例如：
   > *“对于接下来的重构，请列出两种方案并用选择题方式问我”*
2. **预期表现**：
   - 界面上弹出带有多个方案单选框的卡片（如方案 A、方案 B）。
   - EasyAG 判定单选组内不含权限授权关键字（无 allow / 允许 特征），认定为业务方案问答。
   - **绝对不进行自动点击**，卡片保持等待输入状态。
   - EasyAG 打印单条日志，标签类别为 `INTERACTION`，文本为**薄荷荧光青（#00f5d4）**：
     ```text
     [INTERACTION] 方案问答：请选择您偏好的方案...
     ```
   - 不会重复刷屏，只通知一次。

---

### 阶段 5：问答提交之后的解锁（恢复自动审批）
1. **触发操作**：在 IDE 的问答卡片中，鼠标勾选其中一个方案，并点击“Submit”提交。
2. **验证恢复**：问答提交后，Agent 根据您的方案继续执行后续终端命令（如创建文件或执行构建）。
3. **预期表现**：
   - 问答卡关闭后，后续的权限审批卡片再次出现时，能够正常被 EasyAG 识别并自动审批。
   - 说明问答暂停不会造成系统死锁，**方案问答之后的自动审批无缝恢复**。

---

### 阶段 6：高危规则动态重载
1. **触发操作**：
   - 打开 `danger-rules.json`（或点击 EasyAG 界面上的“规则配置”按钮）。
   - 在 rules 数组中临时加入一条新测试规则：
     ```json
     {
       "id": "test-block-echo",
       "name": "测试自定义回显拦截",
       "pattern": "\\becho\\s+EASYAG_TEST_TRAP\\b",
       "flags": "i",
       "enabled": true
     }
     ```
   - 保存文件后，点击 EasyAG 界面的“重载规则”按钮（或发起 POST 请求 `/api/danger-rules/reload`）。
2. **预期表现**：
   - 控制台打印：
     ```text
     [SECURITY] 高危规则已重载: 10/10 条生效 (已实时同步至 CDP 会话)
     ```
   - 整个过程 EasyAG 与 Antigravity 无需重启。

---

### 阶段 7：重载后新增规则拦截校验
1. **触发操作**：让 Agent 执行命中刚刚重载新规则的命令：
   > *“帮我执行 `echo EASYAG_TEST_TRAP`”*
2. **预期表现**：
   - 即使这是一个无害的 `echo` 命令，但因为刚加载了该拦截规则，系统立刻执行拦截。
   - 按钮显示为 blocked，日志出现红色 `[SECURITY ALERT] 拦截高危指令[test-block-echo]`。
   - 拦截后清理规则：测试完毕后在 `danger-rules.json` 中删掉此临时规则，再次点击重载即可恢复。

---

### 阶段 8：日志历史校对与归档验收
1. **操作方式**：打开 EasyAG 的主界面，观察下方日志控制台。
2. **校验清单**：
   - [x] 是否按时序记录了每一步操作？
   - [x] 放行日志是否为绿色 `tag-proxy`？
   - [x] 高危告警是否为红色脉冲动效 `tag-alert`？
   - [x] 方案问答是否为清晰亮丽的薄荷荧光青色 `tag-mint`（`#00f5d4`）？
   - [x] 规则重载是否打印了更新后的生效条数？
   - [x] 界面顶部的已审批计数器与拦截计数器是否与日志中的事件总数完全吻合？

## 四、日志标签与判定准则速查表

| 界面标签分类 | CSS 类名 | 显示色号 | 产生源与含义 |
| :--- | :--- | :--- | :--- |
| **`[AUTO-ACCEPT]`** | `.tag-proxy` | `#00e676` (绿色) | 自动审批放行成功的命令与选项说明 |
| **`[SECURITY ALERT]`**| `.tag-alert` | `#ff3860` (红亮呼吸) | 命中危险规则，熔断拦截并暂停自动点击 |
| **`[INTERACTION]`** | `.tag-mint` | `#00f5d4` (薄荷荧光青)| 检测到方案多选/交互问答卡片，静待用户选择 |
| **`[SECURITY]`** | `.tag-proxy` | `#2979ff` (蓝色/主题色) | 规则文件加载、热重载与规则状态更新 |
| **`[I18N]`** | `.tag-i18n` | `#b388ff` (紫色) | 汉化引擎启用/停用、双向还原事件通知 |
| **`[SYSTEM]`** | `.tag-warn` | `#ffb300` (橙黄色) | 客户端连接/断开、生命周期提示 |
